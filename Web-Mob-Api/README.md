## 📌 О проекте

Комплексное тестирование сервиса **Яндекс.Самокат** по трём направлениям:

1. **Веб-приложение** — экраны «Статус заказа» и «Сделать заказ».
2. **Мобильное приложение** — функциональность, выделенная в требованиях.
3. **API** — бэкенд приложения.

---

## 🎯 Задания

### Задание 1. Веб-приложение Яндекс.Самокат

**Что сделано:**
- Чек-лист по экрану «Статус заказа» — 94 проверки (TW01–TW94).
- Таблица валидации полей экрана «Сделать заказ».
- Тестирование по макетам Figma и требованиям.
- Баги вне тестовой документации.

**Найденные дефекты:**

| Группа | ID | Кол-во |
|--------|-----|:------:|
| Баги по чек-листу «Статус заказа» | BUGW01–BUGW17 | 17 |
| Баги по валидации полей | BUGV01–BUGV14 | 14 |
| Баги вне тестовой документации | BUG-EXT-1 — BUG-EXT-9 | 9 |

**Ключевые дефекты:**
- **BUGW11 (критический)** — статус «Курьер на месте» недоступен; при `status: 2` отображается «Время аренды кончилось».
- **BUGW12 (критический)** — при истечении аренды не добавляется 5-й статус, а меняется название 4-го.
- **BUGW13 (критический)** — система использует дату доставки вместо фактического момента передачи для расчёта времени окончания аренды.
- **BUGW16 (блокирующий)** — отменённый заказ не удаляется из системы и доступен для повторного поиска по номеру.
- **BUG-EXT-4 (критический)** — после выполнения `finish` через API ID заказа изменяется.
- **BUG-EXT-6 (критический)** — бэкенд не валидирует поля при создании заказа.
- **BUGV11 (критический)** — календарь позволяет выбрать прошедшую и сегодняшнюю дату и активирует кнопку «Заказать».

### Задание 2. Мобильное приложение Яндекс.Самокат

**Что сделано:**
- Тест-кейсы по функциональности, выделенной в требованиях — 39 кейсов (MobT01–MobT39).
- Вёрстка по макетам Figma.
- Тестирование на эмуляторе Android Studio Quail 3, Pixel 6, Android 13.0, 1080×2400.

**Найденные дефекты:** BUGMob01–BUGMob12 (12).

**Ключевые дефекты:**
- **BUGMob01 (критический)** — пуш-уведомление приходит раньше времени: в 21:58 уже отображается в шторке.
- **BUGMob02 (блокирующий)** — приложение курьера падает при нажатии на пуш-уведомление (Order notification crash).
- **BUGMob08 (критический)** — приложение падает при многократном тапе по активным кнопкам без интернета.
- **BUGMob09 (критический)** — окно «Нет доступа к интернету» закрывается по тапу вне окна или системной кнопке «Назад».
- **BUGMob10 (критический)** — приложение падает при открытии вкладки «Мои» до принятия заказа (KotlinNullPointerException).

### Задание 3. API приложения Яндекс.Самокат

**Что сделано:**
- Чек-лист по требованиям к бэкенду — 21 проверка (TestApi01–TestApi21).
- Тестирование через Postman.
- Проверки в БД.

**Протестированные ручки:**
- `POST /api/v1/courier` — создание курьера;
- `DELETE /api/v1/courier/:id` — удаление курьера;
- `GET /api/v1/orders/track?t=:track` — получение заказа по треку.

**Найденные дефекты:** BUG-API-01 — BUG-API-05 (5).

**Ключевые дефекты:**
- **BUG-API-03 (критический)** — при передаче `login` как числа возвращается 500 вместо 400.
- **BUG-API-04 (критический)** — при передаче `password` как числа возвращается 201 Created вместо 400.
- **BUG-API-05 (критический)** — при передаче `firstName` как числа возвращается 201 Created вместо 400.

## 🛠 Использованные инструменты и подходы

- **Тест-дизайн:** классы эквивалентности, граничные значения, таблицы принятия решений.
- **DevTools** — проверка запросов и ответов.
- **Charles (Breakpoints)** — подмена ответов API для воспроизведения труднодостижимых состояний.
- **Postman** — тестирование API.
- **SQL** — проверки в базе данных.
- **Эмулятор Android Studio** — тестирование мобильного приложения.
- **Кросс-браузерное тестирование** — Chrome, Яндекс.Браузер.
- **Figma** — сверка вёрстки с макетами.
