# Яндекс Метро — тестирование мобильного приложения (Android)

**Автор:** Наталья Галкина
**Профессия:** Инженер по тестированию

---

## 📌 О проекте

Тестирование мобильного приложения **Яндекс Метро** на Android после рефакторинга кода. Команда внесла правки, и перед выпуском новой версии нужно было протестировать затронутую функциональность, провести регрессионное тестирование и дать заключение — можно ли публиковать новую версию в Google Play.

**Объект тестирования:** приложение Яндекс Метро.
**Тестируемая версия:** 3.6.
**Предыдущая версия (для регресса):** 2.13.
**Окружение:** эмулятор Android Studio (Honor 8) · Android 9.0 Pie · 1080×1920 · 5.2″.

---

## 🎯 Что было сделано

1. **Функциональный чек-лист** — 31 проверка по требованиям, затронутым рефакторингом.

3. **Тестирование** на эмуляторе Android Studio.

## 🐞 Ключевые дефекты

- **БР4 (критический)** — приложение падает при многократной смене ориентации экрана.
- **БР5 (критический)** — при отключении интернета нет уведомления об ошибке. Приложение работает на кэшированных данных, вводя пользователя в заблуждение.
- **БР24 (критический)** — приложение падает при смене ориентации без построенного маршрута.
- **БР7 (высокий)** — при обновлении с v2.13 до v3.6 не сохранились настройки города и языка.
- **БР14 (высокий)** — приложение падает после нескольких переключений темы. Накопительный баг.
- **БР15 (высокий)** — приложение падает при запуске после холодного старта.
- **БР22 (высокий)** — плавающий баг: при лонг-тапе с перемещением пальца карточка станции нестабильно закрывается.

## 💡 Вывод и рекомендации

**Публикацию новой версии не рекомендую.** Три критических дефекта делают приложение нестабильным (падения) и могут ввести пользователя в заблуждение (нет уведомления об отсутствии сети). 23 дефекта высокого приоритета затрагивают важные пользовательские сценарии, включая недавно добавленные проверки отображения деталей маршрута и неподвижности схемы при лонгтапе.

**Приоритеты по исправлению:**

1. Немедленно — критические баги **БР4, БР5, БР24**.
2. Повторное тестирование критических сценариев.
3. Прогнать регресс по блокам «Ориентация экрана» и «Сеть и соединение» — там больше всего дефектов.
4. После исправления — профилирование смены ориентации: замечено постепенное замедление загрузки карты.

## 🛠 Использованные подходы и виды тестирования

- **Функциональное** — проверка требований, затронутых рефакторингом.
- **Регрессионное** — проверка, что новое не сломало старое (обновление с 2.13 до 3.6).
- **Мобильные особенности:**
  - смена ориентации экрана;
  - переключение сетей (3G / LTE / Wi-Fi), симуляция слабого сигнала;
  - работа с геолокацией;
  - прерывания — входящий звонок, уведомление, авиарежим;
  - энергосбережение, низкий заряд;
  - жесты (лонгтап, свайп, пинч);
  - холодный старт.
- **Инструменты:** Android Studio (эмулятор), Logcat, adb, Charles.
