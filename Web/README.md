## 📌 О проекте

Тестирование новой версии приложения **Яндекс Маршруты** с возможностью заказа каршеринга.

Цель работы: составить тестовую документацию, провести проверки по ней, найти дефекты и оформить баг-репорты.

Для тестирования был выбран тариф **«Походный»**.

---

## 🎯 Что было сделано

1. **Чек-лист на вёрстку** формы бронирования и элементов навигационной карты (иконки автомобилей и действия с ними).
2. **Чек-лист + тест-кейсы** на логику окон «Способ оплаты», «Добавление карты» и кнопку «Забронировать».
3. **Тестирование приложения** по составленной документации и заведение баг-репортов.
4. **Отчёт о проделанной работе**.

## 🐞 Ключевые найденные дефекты

- **B27 (критический)** — можно забронировать машину без добавления способа оплаты через сценарий «Добавить права и забронировать». Нарушена ключевая бизнес-логика: оплата обязательна.
- **B29 (критический)** — пользователь может выбрать машину только из ассортимента своего тарифа. Это существенно ограничивает функциональность сервиса.
- **B26** — не открывается окно «Добавление прав» по кнопке бронирования.
- **B4** — удаление адреса приводит к выходу из формы бронирования.
- **B11** — невозможно выбрать машину на карте.
- **B15** — не работает кнопка «Отменить» в окне «Машина забронирована».
- **B24** — в списке карт не отображаются последние 4 цифры, карты не отличить друг от друга.
- **B25** — поле «Способ оплаты» не заполняется после выбора карты.

## 💡 Вывод

Продукт **не готов к передаче пользователям**. Критический баг B27 создаёт угрозу бизнесу (бронирование без оплаты), а 6 блокирующих дефектов ломают основные пользовательские сценарии — от выбора машины до отмены поездки.

**Рекомендации по приоритетам исправления:**

1. Немедленно — критические баги (B27, B29).
2. Срочно — блокирующие баги (B4, B11, B15, B24, B25, B26).
3. Повторное тестирование критических и блокирующих сценариев.
4. Стандартные и желательные баги — в бэклог до релиза.
5. Обсудить с менеджерами добавление функции удаления привязанной карты (сейчас её нет — это не баг, но серьёзное упущение с точки зрения UX).
